# CLOB 交易速率限制

> 按签名者地址划分的 CLOB 下单和取消令牌桶限制

Polymarket 会为每个签名者地址分别设置两个令牌桶，用于评估 CLOB 下单和取消请求。签名者地址是与你的 CLOB API 凭据关联的地址。一个令牌桶中的活动不会占用另一个令牌桶的容量。

<Warning>
  自 2026 年 7 月 24
  日起，限流系统将以警告模式运行两周。在此期间，请求仍会正常处理。如果某个请求在正式限流启用后会被拒绝，响应中的
  `Poly-RateLimit-Warning` 值将为
  `true`。请监控此响应头，并在正式限流启用前调整请求模式。Polymarket
  将另行通知正式限流的启用时间。
</Warning>

<Note>
  这些按签名者地址实施的限制与现有的 [Cloudflare IP
  限制](/cn/api-reference/rate-limits)相互独立，且后者保持不变。
</Note>

## 速率限制的工作方式

每个签名者都有一个订单令牌桶和一个取消令牌桶：

| 令牌桶 | 请求                             | 令牌消耗           |
| --- | ------------------------------ | -------------- |
| 订单  | `POST /order`                  | 1              |
| 订单  | `POST /orders`                 | 非空批次中的订单数量     |
| 取消  | `DELETE /order`                | 1              |
| 取消  | `DELETE /orders`               | 提交的订单 ID 数量    |
| 取消  | `DELETE /cancel-all`           | 1 + 已取消订单数量    |
| 取消  | `DELETE /cancel-market-orders` | 1 + 已取消的匹配订单数量 |

### 令牌补充与突发容量

令牌按照当前等级的速率持续补充。突发容量是令牌桶可以持有的最大令牌数。满桶可以立即消耗全部突发容量；突发容量用尽后，新令牌按补充速率恢复。

完整突发容量对应的持续时间为：

```text theme={null}
burst_seconds = burst / rate_per_sec
```

### 批量请求

正式启用限流后，只有当令牌桶中的令牌足以覆盖批次中的每个条目时，系统才会接受该批次。否则，整个请求会被拒绝，不会处理任何条目。此全有或全无规则仅适用于速率限制检查；通过检查的批次仍保留正常的逐订单响应行为。

如果一个批次的令牌消耗超过当前等级的突发容量，则无法以单个请求的形式被接受。请将其拆分为更小的批次。

### 取消所有订单和取消市场订单

系统无法在 `DELETE /cancel-all` 或 `DELETE /cancel-market-orders` 开始时预先知道将取消多少订单。每个请求会先消耗一个取消令牌。得知取消结果后，每成功取消一个订单，取消令牌桶中还会再扣除一个令牌。

对于允许取消令牌余额为负的等级，第二次扣除可能使取消令牌桶产生欠额。后续取消请求会被阻止，直到令牌桶中有足够令牌处理下一个请求。其他等级会将取消令牌余额下限设为零，无论扣除数量多大。

## 交易量等级

令牌桶按签名者地址划分。等级资格取决于账户钱包（即 maker 钱包）的累计交易量，即使账户钱包与签名者地址不同。当前交易量窗口为 30 天，等级分配每三小时刷新一次。

| 等级       |    30 天交易量 | 下单速率（令牌/秒） | 下单突发容量（令牌） | 取消速率（令牌/秒） | 取消突发容量（令牌） | 允许取消令牌余额为负 |
| -------- | ---------: | ---------: | ---------: | ---------: | ---------: | :--------: |
| Standard |          — |         40 |         60 |         80 |        120 |      是     |
| Copper   |  \$30,000+ |         60 |         90 |        120 |        180 |      是     |
| Bronze   |  \$50,000+ |         80 |        120 |        160 |        240 |      是     |
| Silver   | \$100,000+ |        200 |        300 |        400 |        600 |      是     |
| Gold     | \$500,000+ |        400 |        600 |        800 |      1,200 |      是     |
| Platinum |    \$2.5M+ |        450 |        675 |        900 |      1,350 |      否     |
| Diamond  |      \$5M+ |        525 |        787 |      1,050 |      1,575 |      否     |
| Elite    |     \$10M+ |        600 |        900 |      1,200 |      1,800 |      否     |

随着系统调整，等级阈值、交易量窗口和速率限制可能会发生变化。Polymarket 将提前通知任何重大变更。

## 响应头

当限流器成功评估上述请求时，响应会包含以下响应头：

| 响应头                        | 说明                   |
| -------------------------- | -------------------- |
| `Poly-RateLimit-Remaining` | 完成限流记账后，适用令牌桶的当前令牌余额 |
| `Poly-RateLimit-Reset`     | 当前限流等待期结束的 Unix 时间戳  |
| `Poly-RateLimit-Tier`      | 应用于该请求的速率限制等级        |

以下响应头仅在特定情况下出现：

| 响应头                      | 说明                              |
| ------------------------ | ------------------------------- |
| `Retry-After`            | 重试延迟（秒）；仅包含在 `429` 响应中          |
| `Poly-RateLimit-Warning` | 在警告模式下，正式启用限流后会被拒绝的请求将返回 `true` |

`Poly-RateLimit-Reset` 并不表示令牌桶恢复至满容量的时间。对于令牌消耗未超过突发容量的 `429` 响应，它表示预计何时会有足够令牌处理该请求。对于已接受的请求，它可能是当前时间戳。

对于允许取消令牌余额为负的等级，`DELETE /cancel-all` 或 `DELETE /cancel-market-orders` 执行后，`Poly-RateLimit-Remaining` 可能为负数。发送大批量请求前，请将其令牌消耗与剩余余额进行比较。

## 处理 429 响应

正式启用限流后，如果请求所需的令牌多于适用令牌桶中的可用令牌，系统将返回 `429 Too Many Requests`。

如果请求的令牌消耗未超过当前等级的突发容量，`Retry-After` 会给出重试前的最短等待时间。你无需等待桶完全补满。如果请求的令牌消耗超过突发容量，请将其拆分为更小的请求，而不是原样重试。

## 获取帮助

如果你对等级有疑问，认为钱包符合更高等级的条件，最近将交易活动迁移到新地址，或认为自己被错误限流，请联系 [support@polymarket.com](mailto:support@polymarket.com)。
